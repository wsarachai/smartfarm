# lora-gateway/

- `lora-gateway/` — **PlatformIO / Arduino (STM32duino)** firmware for a **second NUCLEO-WL55JC1** — the **RX-only counterpart to `water-temp-node`**. Same framework rationale as above. Listens continuously on the shared AS923 channel (shares the node's `src/lora/*` + `include/hal_conf_extra.h` as **byte-identical copies** — change both together), validates CRC-8, maps `node_id → device_id` (`include/gateway_config.h`; unknown → `water-node-<id>`), and prints **one JSON line per frame** out `Serial`/VCP (adding `rssi`/`snr`/`seq`; invalid temps omitted; `#`-prefixed diagnostic lines). Decodes **v1..v5** and emits whichever metrics the frame marks valid (`air_temp`/`humidity`/`pressure`/`co2` on top of the water temps + battery), asking `lora_probe_valid()` per probe because v4's extra probes carry validity as the `0x8000` sentinel rather than a flag bit — `flags` has no spare bits left. `LED_BUILTIN` blinks per RX. Its host companion **`lora-gateway/bridge/`** is a standalone **Node.js + `serialport`** forwarder (kept out of `web-server/` to keep it hardware-agnostic, like the AI poller): reads the gateway's `/dev/ttyACM0` (or `COMx`), validates, and POSTs each line to `/api/v1/telemetry` (`SERVER_URL`); auto-reconnects; needs Node ≥ 18 (global `fetch`); `.env` via `--env-file`. So the full path is **node (LoRa) → gateway (WL55, RX) → bridge.js (USB→HTTP) → web-server:3000**, no LoRaWAN/gateway-vendor stack. Dashboard shows `water-temp-01` with `temp_hot`/`temp_cold`/`temp_p2`..`temp_p5`/`air_temp`/`humidity`/`air_temp_2..3`/`humidity_2..3`/`battery_v`/`rssi`/`snr` — metric naming lives in `gw_probe_metric()`/`gw_air_metric()`/`gw_hum_metric()` (`include/gateway_config.h`), with probes 0/1 and air sensor 0 keeping their historic labels so existing dashboard history stays one continuous series. **Verified: compiles clean** (`pio run`) — RAM 1.9%, Flash 9.7%.
