# water-temp-node/

- `water-temp-node/` — **PlatformIO / Arduino (STM32duino)** firmware for a **NUCLEO-WL55JC1** (STM32WL55JC, `board = nucleo_wl55jc`, `framework = arduino`, flash via onboard/external **ST-Link**). A **battery-powered LoRa** multi-probe **water-temperature** (up to 6) + **air/CO2** sensor node — the repo's **first non-ESP, first LoRa, first sub-GHz** device. **Why `arduino` not `stm32cube`:** PlatformIO's ststm32 platform has **no** stm32cube framework for the STM32WL family (no `framework-stm32cubewl` package exists in the official *or* maxgerhardt platforms; the WL board advertises only `arduino`/`zephyr`). But **STM32duino *is* the STM32Cube HAL underneath**, so the intended HAL SubGHz driver compiles unchanged — we just enable `HAL_SUBGHZ` via `include/hal_conf_extra.h` (the STM32duino override hook). Every `WAKE_INTERVAL_S` (default 15 min) it wakes from **Stop2** (raw-HAL `HAL_PWREx_EnterSTOP2Mode` + RTC/LSE wake on the CM4 `RTC_WKUP_IRQn` — **not** the STM32LowPower lib, whose 2.0.0 release `#error`s against the core PlatformIO bundles), powers **6× DS18B20** (one per GPIO, SKIP-ROM, so they convert in PARALLEL — one 750 ms wait, not six; P0=PA5 P1=PA4 P2=PA9 P3=PC2 P4=PC1 P5=PB10) through an **AO3401A P-MOSFET** high-side gate (PA8, active-low, whole rail incl. pull-ups; 100k gate pull-up = OFF while Hi-Z), reads both temps (12-bit, hand **bit-banged**, `ds18b20.cpp`, `delayMicroseconds` timing), reads **THREE SHT45s** (air temp/humidity, all I2C 0x44, behind a TCA9548A bus switch at 0x70 — see below) and an **SCD41** (CO2, I2C 0x62, upstream of the switch) on **PA11=SDA/PA12=SCL** off the *same* gated rail (gate = **PA8**, active-low), measures the battery via the internal **VREFINT** (STM32duino `analogRead(AVREF)`, no external parts; assumes battery *is* the 3.0–3.6 V rail), TX's **one uplink** (AS923 **923.2 MHz SF9BW125 CR4/5 14 dBm**), then sleeps. **Uplink-only** (never listens). It can't reach the HTTP web-server directly, so a **36-byte binary frame v5** (`src/lora/lora_packet.h`: magic/nodeId/seq/flags/probe0·probe1 int16 centi-°C/battery_mv/air_temp0·humidity0/pressure/co2/probe2..probe5/air_temp1·humidity1·air_temp2·humidity2/CRC-8) goes to **`lora-gateway/`**. **v4 (2026-08) widened the water temperatures from 2 probes to 6 and is purely additive**: probes 0/1 stay in v1's original two slots with their HOT/COLD flags, so v1/v2/v3 are byte-unchanged and an older two-probe node keeps working and keeps its metric names; probes 2-5 are appended after `co2`. **It adds no valid-flags and cannot** — all eight `flags` bits are spoken for (a v5 needing one must add a second flags byte) — so probes 2-5 signal 'no reading' with the existing `LORA_TEMP_INVALID` (0x8000) sentinel, and `lora_probe_valid()` in the shared header is the ONE place that knows probes 0/1 gate on a flag while 2-5 gate on the sentinel; node, gateway and the Python receiver all call it rather than testing either by hand. A probe that is not fitted needs no config change: an unconnected line sees no presence pulse, goes out as the sentinel, and is dropped by the gateway rather than appearing as a convincing 0.00 degC. **v5 (2026-08) then widened the air sensors from 1 SHT45 to 3**, same additive rule (v1-v4 byte-unchanged, air sensor 0 stays in the v2 slots with its AIR/HUM flags, sensors 1-2 appended after the probes and gated by sentinels — `LORA_TEMP_INVALID` for temperature and the new `LORA_HUM_INVALID` 0xFFFF for humidity, since %RH's valid range is 0..10000). `lora_air_valid()`/`lora_hum_valid()` are the air-side counterparts of `lora_probe_valid()`. Airtime grows ~41 ms per 8 bytes at SF9BW125 (20 B ~185 ms, 28 B ~226 ms, 36 B ~267 ms); the whole v3->v5 growth is ~4 mAs/wake — irrelevant beside the SCD41 — and costs no extra rail-on time at all. The LoRa driver (`src/lora/subghz_lora.c`, called from `main.cpp` via `extern "C"`) is a lean **self-contained SX126x command driver over `HAL_SUBGHZ`** — deliberately **not** the full CubeWL SubGHz_Phy middleware; RF-switch truth table (FE_CTRL1=PC4, FE_CTRL2=PC5, FE_CTRL3=PC3) + TCXO-on-DIO3 taken verbatim from ST's NUCLEO-WL55JC BSP. No `secrets.h` (raw LoRa needs no keys); config in committed `include/node_config.h`. Debug log on `Serial` (LPUART1 → ST-LINK VCP). **Verified: compiles clean** (`pio run`) — RAM 3.1%, Flash 15.4%. **DS18B20 bring-up test (`[env:bluepill_f103c8]`):** while the WL55 boards are on back-order, a second PlatformIO env reuses the **same `ds18b20.cpp`** (via `build_src_filter`, no copy) on an **STM32F103C8T6 Blue Pill** to validate the sensor + wiring — `src/test/ds18b20_test_main.cpp` reads two probes (hot=PB6, cold=PB7, direct 3V3, PC13 LED) and prints over **USB CDC** at ~1 Hz; `ds18b20.h` was made family-agnostic (`#include <Arduino.h>`) so it compiles on both targets. **Hardware-verified on the F103** (both probes track real, independent temperature). The F103 prototype grew several extra envs (all reusing the shipped drivers via `build_src_filter`, none affecting the WL55 build): **`[env:bluepill_f103c8_semihosting]`** — same DS18B20 test but output via **ARM semihosting over SWD** (`-DUSE_SEMIHOSTING`, `BKPT 0xAB`/`SYS_WRITE0`, viewed in the OpenOCD/VSCode Debug Console) for when a clone Blue Pill's native USB won't enumerate; **`-DDS18B20_INTERNAL_PULLUP`** uses the MCU's internal ~40k pull-up when no external 4.7k is on hand (short bench bus only); without it `ds18b20_init()` takes the `GPIO_NOPULL` path for an external resistor. Because that is a property of the **bench wiring**, not of a build, it is set in **one** place — `ds18b20_pullup` in `platformio.ini`'s `[bluepill_base]`, interpolated by every F103 env (the WL55 env never sets it — the real node always has its resistors). **Currently: external 4.7k per line, hardware-verified** reading both probes. A **`[env:bluepill_f103c8_dump]`** diagnostic env (+ `ds18b20_read_scratchpad()`) prints the raw 9-byte scratchpad and probes each DQ pin's idle level (internal pull-up vs pull-down) — `pull-up=1 pull-down=1` proves an external resistor is really on 3V3, `pull-up=0 pull-down=0` means the line is held low (resistor tied to GND / short), all-zero bytes mean a stuck-low bus. Added after a rewire held both DQ lines low. **`tools/watch.ps1`** wraps flash + semihosting-attach into one command (`tools/watch.ps1 [-PioEnv <env>] [-NoUpload]`), resolving pio/openocd under `~/.platformio` and killing a leftover openocd that would otherwise block the ST-Link. Also: `ds18b20_read()` now **rejects an all-zero scratchpad** (stuck-low bus passes CRC → fake 0.00 °C) — a fix that benefits the WL55 node too. **Long DS18B20 runs (10–20 m):** plain 1-Wire handles it (Maxim **AN148**) — **not** RS-485 (a MAX485 *cannot* sit on the 1-Wire line: it's a directional differential UART transceiver, 1-Wire is bidirectional open-drain reversing direction mid-bit-slot). Fit an **external ~2.2 kΩ** pull-up (not the internal ~40 kΩ; drop `DS18B20_INTERNAL_PULLUP`), **twisted-pair DQ+GND**, keep 3-wire VDD power; no firmware timing change. Escalate to a **DS2483/DS2480B** 1-Wire line-driver IC (active pull-up), or a remote MCU digitizing + RS-485/Modbus, only past ~30 m. See `water-temp-node/README.md` "Long DS18B20 runs". **Real-hardware design (`water-temp-node/docs/hardware-interface.md`):** the spec for the non-breadboard build, fixed as **two PCBs joined by a CABLE** — the NUCLEO-WL55JC1 (brain) + a **large custom front-end PCB** sitting beside it (the connector decision is spelled out below). Earlier never-built revisions of this spec (a morpho-stacking board, then an ARDUINO shield) have been **deleted from the doc** — if you meet a stale reference to `PB2`, `DQ_HOT`/PA10 or CN5/CN8 pin numbers anywhere, it is dead config, not an alternative. **Twelve signals** cross the joint (`VBAT`/2x`GND`/`SENS_GATE` PA8 active-low/`DQ_P0..P5`/`I2C_SDA`/`I2C_SCL`); `VSENS` (the gated rail) is generated on the front-end and never crosses back. **The three SHT45s add ZERO signals**, which is why they are arranged the way they are: the SHT4x I2C address is fixed at the factory by the order code (`SHT45-AD1B` = 0x44, no address pin), so three cannot share a bus — and **individually power-gating them does not work**, which is the trap worth remembering. An unpowered SHT45 still clamps SDA/SCL to its own VDD through its ESD diodes, so the 4.7k bus pull-ups phantom-power it to ~2.7 V (the part runs from 1.08 V) and it answers at 0x44 anyway; no pull-down value escapes it (10k leaves it alive at ~1.8 V, 1k kills it but clamps SDA to ~1.1 V, under the 2.31 V VIH). **What has to be switched is the BUS, not the power** — hence a **TCA9548A** (`src/tca9548a.{h,cpp}`, one channel at a time), which is itself an I2C device and so costs no pins and no connector signals. The SCD41 (0x62) collides with nothing and sits UPSTREAM of the switch. Sensor index = mux channel = frame slot = dashboard metric (`I2C_MUX_CHANNELS` in `node_config.h`); three identical 0x44 parts are otherwise indistinguishable, so the channel number is silkscreened next to each. Each downstream channel needs its OWN 4.7k pull-ups (the mux passes signals, not pull-ups). `main.cpp` hides all of it behind one `sht45_select(i)`. Front-end schematic + BOM (2.2k pull-ups **on the switched rail** so a gated-off probe can't leak, 100R series, low-C TVS, `VSENS` bulk bounded by the 10 ms `DS_POWER_SETTLE_MS`), the two Nucleo battery traps (ST-LINK draws mA — snap it off or feed 3V3 direct; **DS18B20 needs ≥3.0 V** so 2×AA alkaline is out, LiFePO4/lithium-AA in), and a bring-up order. Note `battery_read_mv()` (VREFINT) is only valid while the battery *is* VDDA — inserting a regulator breaks it. **`[env:bluepill_f103c8_sx1278]`** — bench self-test of an **external SX1278 (SX127x) LoRa module** (`src/sx1278.{h,cpp}`, Arduino SPI; a *different* chip/registers from the WL55's internal SX126x): SPI probe (RegVersion==0x12) → 433 MHz SF9/BW125 TX beacon; **hardware-verified** (RegVersion OK + TxDone). **`[env:bluepill_f103c8_node]`** — the full prototype **node**: DS18B20 → the shared **12-byte `lora_packet.h`** frame → SX1278 TX @433 (NSS=PA4 SCK=PA5 MISO=PA6 MOSI=PA7 RESET=PB0 DIO0=PB1); **hardware-verified** (reads probes + TxDone). This F103+SX1278 node is the 433 MHz prototype that pairs with **`lora-pi-receiver/`** (SX1278 = 433 MHz, so it does **not** reach the 923 MHz WL55 gateway — separate prototype path while the WL55 boards are on back-order). **`[env:bluepill_f103c8_node_standalone]`** is the same node **without** semihosting so it runs autonomously on any USB/battery power (the semihosting `BKPT` faults with no debugger attached; `out()` falls back to a harmless UART `Serial`) — flash it once and just power the board. **End-to-end HARDWARE-VERIFIED (2026-08):** F103 node → SX1278 433 → Pi SX1278 (SPI) → `lora-pi-receiver/receiver.py` → web-server accepted (HTTP 2xx), dashboard `water-temp-01` `temp_hot`/`temp_cold` matched the node exactly at RSSI ≈ −64 dBm / SNR ≈ 13 dB. **BME280 added (2026-08):** the node envs also read a **BME280 on I²C2 (PB10=SCL/PB11=SDA — I²C1/PB6-7 is the DS18B20 bus)** via the Adafruit BME280 lib and send **ambient air_temp/humidity/pressure** in an **18-byte frame v2** (magic `0xA2`). `lora_packet.h` gained v2 **additively** (`lora_packet_pack_v2`, new flags/fields) — **v1/12-byte is unchanged so the WL55 923 MHz path is untouched**; only the F103+BME280 433 path sends v2. `lora-pi-receiver/lora_packet.py` decodes **both** v1 and v2; `receiver.py` adds `air_temp`/`humidity`/`pressure` metrics. **SHT45 + SCD41 added (2026-08):** the node gained two more I²C sensors — a **SHT45** (air temp/humidity, 0x44) and a **Sensirion SCD41** (true photoacoustic NDIR **CO2**, 0x62) — on **both** the WL55 node and the F103 prototype, in a **20-byte frame v3** (magic `0xA3`) that appends `co2` to v2's layout; **v1/v2 are byte-unchanged**, and `lora_packet_unpack()` now accepts all three so an older node keeps working. Drivers are **hand-rolled from the datasheets** (`src/sht45.{cpp,h}`, `src/scd41.{cpp,h}`) over a shared `src/sensirion_i2c.{cpp,h}` helper (Sensirion word protocol: 16-bit BE words each followed by **CRC-8 poly 0x31/init 0xFF** — deliberately *not* the frame's `lora_crc8`, poly 0x07/init 0x00) — no vendor library, so the WL55 env still has **zero `lib_deps`**. **SHT45 supersedes the BME280 for air temp/humidity** (±0.1 °C/±1 %RH beats it); the BME280 keeps `pressure` only, and `LORA_FLAG_SHT` (bit 7) records which part supplied T/RH — same units either way, so it is *not* emitted as a metric (dashboard history stays continuous) but is logged once per node by `receiver.py`, and again only on change. **Two CO2 modes, because the hosts differ:** the mains-powered F103 runs the SCD41 **periodic** (free-running 5 s, cell stays warm, more accurate) and feeds the BME280 pressure back via `scd41_set_ambient_pressure()` (~1 % of reading per 10 hPa); the battery WL55 uses **single-shot** — 5 s per shot, and since the datasheet's first shot after power-up is unsettled, **two** shots (`CO2_SINGLE_SHOT_WARMUP`) ≈ 10 s of sensor-on time. That makes CO2 the node's dominant energy cost, so it is paced by `CO2_EVERY_N_WAKES` (default **4** → one reading/hour at the 15-min wake, a **0.28 %** duty cycle vs 1.1 %), re-sending the cached value in between with the flag still set. WL55 pins: **I2C2 PA11=SDA/PA12=SCL** (I2C1 wants PA9/PA10 = the probes; I2C3 wants PB11 = the Nucleo's **LED3**), both parts on the **same gated VSENS rail** as the probes — `sensor_pins_park()` now parks the I2C pins analog too, and `I2C_POWER_SETTLE_MS` (1000 ms, the SCD41's power-up time) is **overlapped** with the DS18B20 conversion so the rail is on for the longer of the two, not the sum. `docs/hardware-interface.md` updated: the connector contract grew from **six signals to eight** (+SDA/SCL) and then to **twelve** (+four more probe lines — **older front-end boards are not forward-compatible at any of these steps**), the SCD41's **~205 mA peaks** now size Q1 and the rail bulk/traces, and the enclosure must be **vented** (a sealed box measures its own interior's CO2). **The front-end is now a LARGE CUSTOM PCB joined by a CABLE, not a shield and not a morpho-stacking board** (switched 2026-08, after the ARDUINO-shield revision it replaces): six probe connectors + the two I2C parts + protection + battery input do not fit a 68.6×53.4 mm Uno outline, and once the board must be its own size the shield's only advantage (free keying from the outline) is gone anyway. **Two cables, deliberately split:** all **12** logic signals ride ONE 2×19 IDC ribbon on **morpho CN10** (`SENS_GATE`(**PA8**)→CN10-16, `DQ_P0..P5`→CN10-11/17/19/21/23/25, `I2C_SDA`(PA11)→CN10-5, `I2C_SCL`(PA12)→CN10-3, `GND`→CN10-9 **and** CN10-20), while battery power takes its **own keyed 2-pin lead** to **CN6-4/6/7**. Keeping `VBAT` off the ribbon is the point: a 2×19 socket on unshrouded morpho pins *can* be pressed on 180°-rotated, and with power split out the worst case is two open-drain GPIOs shorted to ground instead of battery voltage on a GPIO. **Keying is a physical stop, not a silkscreen arrow:** clip the **CN10-6** pin (it is NC) and plug the matching IDC hole — rotated, that hole lands on populated pin 33 (PB12) and the socket will not seat. **Use full-length sockets** (2×19 over all of CN10, 1×8 over all of CN6 with only 4/6/7 wired) so neither can be fitted one position out. Ribbon ≤30 cm. **Probe pins are placed by ribbon adjacency, not convenience** — six bit-banged open-drain lines in one flat cable is the new SI problem, so each DQ sits next to a **GND (CN10-9/20)** or an **NC (6/10/18/24/34, groundable at the front-end end only, as a one-ended guard)**; every other conductor floats at the front-end. **`SENS_GATE` is PA8** (CN10-16, inside the DQ block, no boot strap so it resets floating and the 100k holds the rail off), and **PA10 is deliberately unused** — a fine 1-Wire pin, but on CN7, and one line does not justify a second ribbon. **The do-not-route list is real again** — cabling to the morpho puts PC3/PC4/PC5 (RF switch), PB0 (TCXO), PA13/PA14 (SWD), the VCP, AVDD/AGND, all three buttons (PA0/PA1/PC6) and all three LEDs (PB9/PB11/PB15) back in reach — but SWD *can* now be brought out to a debug header, which the shield could not. Caveat recorded in the doc: SCL at CN10-3 sits between the RF-switch conductors CN10-2/4, tolerable only because the firmware gates the sensor rail off **before** powering the radio, so I2C is never active while those switch — do not reorder that sequence in `main.cpp`. The verified **morpho CN7 map** is retained as **Appendix A** for bench probing (CN10 is now in the main text), including that **CN7-33 `VBAT` is the RTC backup pin, NOT a power input** (a trap the shield could not reach and this revision can), and that **Table 18 has an erratum** — CN10-37 is printed `PB6 / PA3` but is `PB7 / PA3` (PB6 is already at pin 35, PB7 appears nowhere in a table whose preamble says all I/Os are present, and the UM's own note says D0/D1 = PB6 **and** PB7). Also flagged: UM2592 Table 17 labels PA11/PA12 `I2C1_*` while STM32duino's `PeripheralPins.c` and Zephyr both say **I2C2** — harmless for the firmware (STM32duino resolves the instance from the pin map) but check RM0453 before any bare-HAL port. Compile-verified; Python decode **unit-tested** by `lora-pi-receiver/test_lora_packet.py`, whose vectors are generated by compiling the firmware's own `lora_packet.h` on the host (v1/v2/v3, negative temps, invalid-probe sentinel, every single-byte corruption). Flash sizes: WL55 15.5%, node 52.9%, standalone 55.0%, sx1278 25.4%, semihosting DS18B20 ~40%.
